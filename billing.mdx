E2B uses [usage-based pricing](#usage-based-pricing) - you pay only for what you use. New users receive $100 in free credits to get started.

[Manage billing in console](https://console.e2b.dev/?tab=billing)

## API rate limits

E2B applies rate limits to API requests. The following default limits are in **requests per second, per project, per endpoint**:

<div className="api-rate-limits-table">

| Endpoint | Hobby | Pro | Enterprise |
|:---------|------:|----:|-----------:|
| [`GET /sandboxes`](/api-reference/sandboxes/list-sandboxes) | 10 | 20 | Custom |
| [`GET /v2/sandboxes`](/api-reference/sandboxes/list-sandboxes-v2) | 10 | 20 | Custom |
| [`GET /sandboxes/metrics`](/api-reference/sandboxes/list-sandbox-metrics) | 10 | 20 | Custom |
| [`GET /snapshots`](/api-reference/sandboxes/list-snapshots) | 10 | 20 | Custom |
| [`GET /templates`](/api-reference/templates/list-templates) | 10 | 20 | Custom |
| [`GET /v2/templates`](/api-reference/templates/list-templates-v2) | 10 | 20 | Custom |
| [`GET /templates/{templateID}`](/api-reference/templates/get-template) | 10 | 20 | Custom |
| [`GET /templates/{templateID}/tags`](/api-reference/tags/list-template-tags) | 10 | 20 | Custom |
| [`GET /api-keys`](/api-key) | 10 | 20 | Custom |
| [`GET /volumes`](/api-reference/volumes/list-team-volumes) | 10 | 20 | Custom |
| [`GET /secrets`](/api-reference/secrets/list-secrets) | 10 | 20 | Custom |

</div>

<Note>
Enterprise plans come with API rate limits sized to your workload. [Book a call](https://e2b.dev/contact) with our team or contact us at [enterprise@e2b.dev](mailto:enterprise@e2b.dev) to discuss your limits.
</Note>

You share each endpoint's limit across all API keys and clients in your [project](/projects). Requests to one endpoint do not consume another endpoint's allowance. For endpoints with a path parameter, such as `/templates/{templateID}`, requests for different template IDs share the same allowance.

These limits include requests made through the SDKs and CLI. Each request for a page of results counts toward the limit.

### Exceeding a limit

If you exceed a limit, you receive an HTTP `429 Too Many Requests` response with a `Retry-After` header.

Starting with version **2.49.1**, the E2B JavaScript and Python SDKs automatically retry these requests using the `Retry-After` delay.

If you handle retries yourself, wait the number of seconds in `Retry-After` before retrying the request.

### Requesting a higher limit

To request a higher API rate limit, contact [support@e2b.dev](mailto:support@e2b.dev). For custom limits on the Enterprise plan, [contact sales](mailto:enterprise@e2b.dev).

## Usage-based pricing

You pay per second for compute resources while your sandbox is running.

Upgrading to the Pro tier does not grant additional credits. It only increases the limits available to your project (such as concurrent sandboxes, continuous runtime, and resource ceilings).

### Compute costs

Use the [usage cost calculator](https://e2b.dev/pricing#:~:text=Usage%20Cost%20Calculator) on our pricing page to estimate costs for your specific configuration.

### Customizing compute resources

You can customize allocated CPU and RAM when building custom templates by specifying `cpuCount` and `memoryMB` in the build configuration.

<CodeGroup>
```js JavaScript & TypeScript
import { Template, defaultBuildLogger } from 'e2b'

await Template.build(template, 'my-template', {
  cpuCount: 8,
  memoryMB: 4096,
  onBuildLogs: defaultBuildLogger(),
})
```
```python Python
from e2b import Template, default_build_logger

Template.build(
    template,
    'my-template',
    cpu_count=8,
    memory_mb=4096,
    on_build_logs=default_build_logger(),
)
```
</CodeGroup>

See [template quickstart](/template/quickstart) for more details on building custom templates.

<Note>
Need higher CPU or RAM limits? Contact [support@e2b.dev](mailto:support@e2b.dev) for more information.
</Note>

## FAQ

<AccordionGroup>
  <Accordion title="When am I charged?">
    Automatically at the start of the month for the previous month's usage.
  </Accordion>

  <Accordion title="What happens when I run out of credits?">
    Your account will be blocked. Add a payment method to continue using E2B.
  </Accordion>

  <Accordion title="Can I set spending limits?">
    Yes, you can set spending limits on the [budget page](https://console.e2b.dev/?tab=budget) in your dashboard.
  </Accordion>

  <Accordion title="How do I optimize costs?">
    - **Enable auto-pause** - Automatically pause sandboxes after a period of inactivity to stop billing while preserving state
    - **Pause sandboxes when idle** - Use `sbx.pause()` to stop billing while keeping state available for later
    - **Kill sandboxes you no longer need** - Use `sbx.kill()` to stop billing and release resources permanently
    - **Allocate only what you need** - Start with default resources (2 vCPU, 512 MiB RAM) and increase only if necessary
    - **Monitor actively running sandboxes** - Use the [CLI](/cli/list-sandboxes) or [console](https://console.e2b.dev/?tab=usage) to track active sandboxes
    - **Use lifecycle events** - Set up [webhooks](/sandbox/lifecycle-events-webhooks) to get notified when sandboxes are created
  </Accordion>

  <Accordion title="Do I pay for stopped sandboxes?">
    No. You only pay while a sandbox is actively running. Once a sandbox is paused, killed or times out, billing stops immediately.
  </Accordion>
</AccordionGroup>
