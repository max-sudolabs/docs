## E2B Embed & Automatic 429 Retries

This week adds E2B Embed, automatic SDK retries, and an OpenAI Agents API guide with public examples.

### E2B Embed for self-hosted deployments

Run E2B on your infrastructure with Docker Compose, Terraform, or Kubernetes deployments and pinned service images. ([`c20cb30`](https://github.com/e2b-dev/infra/commit/c20cb3049f34011eb9704445fa08c09baf24a480), [`7278c2a`](https://github.com/e2b-dev/infra/commit/7278c2a380767c9989da73cf4c04b1af1b32da18))

### Automatic 429 retries in the SDKs

Control plane HTTP requests retry up to three times on 429, honoring delta-seconds `Retry-After`. Configure or disable with `retries`. Sandbox command, filesystem, and volume content requests are not retried. Shipped in the JavaScript and Python SDKs 2.49.1. ([#1848](https://github.com/e2b-dev/E2B/pull/1848), [#1862](https://github.com/e2b-dev/E2B/pull/1862))

### Configurable minimum free disk on template create

Set a [template build](/template/build) free-disk target with `minFreeDiskMb` (JavaScript), `min_free_disk_mb` (Python), or `--min-free-disk-mb` (CLI). Omission uses the project default. Zero requests no minimum growth. Shipped in the JavaScript and Python SDKs 2.49.0 and CLI 2.19.0. ([#1845](https://github.com/e2b-dev/E2B/pull/1845))

### Dedicated E2B client on Desktop and Code Interpreter

The Desktop and Code Interpreter `E2B` clients bind API keys and domains explicitly. Per-call options take precedence, and clients stay isolated. Shipped in Desktop 2.4.0, desktop-python 2.5.0, code-interpreter 2.8.0, and code-interpreter-python 2.10.0. ([#1783](https://github.com/e2b-dev/E2B/pull/1783), [#1784](https://github.com/e2b-dev/E2B/pull/1784))

### Sharper SDK error surface

HTTP 503 raises `ServiceBusyError` or `ServiceBusyException`. API errors expose `statusCode` or `status_code`. `Sandbox.create` and `Sandbox.connect` reject invalid `onTimeout` and `onResume` values. Shipped in the JavaScript and Python SDKs 2.48.0 and 2.49.1. ([#1832](https://github.com/e2b-dev/E2B/pull/1832), [#1822](https://github.com/e2b-dev/E2B/pull/1822), [#1853](https://github.com/e2b-dev/E2B/pull/1853))

### New integration and reference guides

The [OpenAI Agents API guide](/agents/openai-agents-api) includes public Workbench and webhook-managed examples. Requires OpenAI Agents API preview access. New reference docs cover [Volumes beta limitations](/faq/volumes-beta-limitations), [Secrets management and injection](/secrets), and [exported OTel metrics](/sandbox/otel-telemetry-export). Volumes and Secrets remain in private beta.

### Fixes

- Desktop `Sandbox.create()` waits for the desktop session to be ready and cleans up on startup failure. Shipped in Desktop JavaScript 2.4.0 and Python 2.5.0. ([#1794](https://github.com/e2b-dev/E2B/pull/1794))
- Self-hosted `REDIS_URL` accepts passwords in `redis://` and `rediss://` URLs without exposing raw URLs in parse errors. ([`29462af`](https://github.com/e2b-dev/infra/commit/29462afe56fd06b10b77e5ae2cf0b07a1c313f7d), [`ae13f0c`](https://github.com/e2b-dev/infra/commit/ae13f0cbe5d5d11d4c947a07e73b299370475e81))
- Fixed openssh upgrades blocking template builds on configuration-file prompts. ([`52df1d9`](https://github.com/e2b-dev/infra/commit/52df1d987c47cd3cdde92d828a59b1e64b8bbf38))
- CLI 2.18.2 skips update checks when `NO_UPDATE_NOTIFIER` is set. ([#1837](https://github.com/e2b-dev/E2B/pull/1837))
- Reliability and security hardening across platform services, including dependency and base image CVE patches.

</Update>

## Workspaces & Cursor Integration

Workspaces are rolling out in the console, and new templates connect Cursor Self-Hosted Machines to E2B. This week also adds HTTPS backend ports, higher Python SDK concurrency, and new integration guides.

### Workspaces are rolling out

[Workspaces](/workspaces) bring your projects and access management into one place in the E2B Console. Add members to a workspace to give them access to all its projects, or add them to an individual project. Existing projects and API keys keep working, and billing remains per project.

### Cursor self-hosted agents on E2B

Run Cursor Self-Hosted Machines on E2B with the new `cursor-agents` dispatcher and `cursor-agents-worker` templates. The dispatcher creates a dedicated worker sandbox for each request. Requires Cursor Enterprise with Self-Hosted Machines enabled and a service-account API key. Follow the [Cursor setup guide](/agents/cursor).

### HTTPS backend ports on sandbox create

Sandbox creation accepts a `network.httpsPorts` list naming the ports the platform connects to over HTTPS, so a service inside the sandbox that only serves TLS can sit behind its public URL instead of failing with a 502. The list survives pause and resume and is returned on sandbox reads. ([`b5f419a`](https://github.com/e2b-dev/infra/commit/b5f419a2b122f8ff881497681bde0d109cbbf0fe))

### Higher stream concurrency in the Python SDK

The Python SDK now spreads each sandbox's command and file traffic across four connection pools by default, so running more than 100 concurrent operations in one process no longer stalls behind a single connection's stream limit. Set `E2B_ENVD_POOL_SHARDS` before importing `e2b` for more headroom. Shipped in the Python SDK 2.46.4. ([#1793](https://github.com/e2b-dev/E2B/pull/1793))

### Self-hosted deployments without Loki

Self-hosted deployments can now run without a Loki instance: the `LOKI_URL` variable is optional, and the new `LOGS_READ_CONFIG` variable selects the backend used for reading sandbox logs. ([`8006b78`](https://github.com/e2b-dev/infra/commit/8006b7863ee201e60a25e83e5d9cb6ab364e98b0))

### Dashboard sandbox quickstart

The dashboard now opens on the sandbox list, and when a project has no running or paused sandboxes the list shows a quickstart with copyable CLI, JavaScript, and Python steps for creating a first sandbox from the `base` template.

### New integration guides

New guides cover [Agno](/agents/agno), [NVIDIA NeMo Gym](/agents/nemo-gym), and [Muse Code](/agents/muse).

### Fixes

- Template builds from minimal RPM-family base images, such as Rocky Linux minimal or UBI, no longer fail during the final build step. ([`12ee9b1`](https://github.com/e2b-dev/infra/commit/12ee9b1062d59a76c5d6b2df26e3e53c66fdbc08))
- Fixed commands in a resumed sandbox running as root instead of the sandbox's default user after a platform upgrade. Affected sandboxes recover on their next resume. ([`972e9d3`](https://github.com/e2b-dev/infra/commit/972e9d33bcaa37349c4d81608b45dd4c4a6cb33e))
- Fixed log lines written shortly before a pause being dropped from sandbox logs after resume. ([`e915d32`](https://github.com/e2b-dev/infra/commit/e915d32bfc471a5e102419549db4ab977efa027c))
- Fixed sandbox pause reporting a failure when a process inside the sandbox exited while the pause was in progress. ([`27eefde`](https://github.com/e2b-dev/infra/commit/27eefded9fc16f0043c023222eec18882c08862c))
- Volume uploads rejected mid-transfer now return the actual rejection status instead of a generic failure.
- Reliability and security hardening across platform services, including dependency and base image CVE patches.

</Update>

## Wildcard Transform Rules & Server-Side API Key Validation

This week improves sandbox networking and authentication with wildcard domains in transform rules, server-side API key validation, and readable proxy errors for browser requests.

### Wildcard domains in network transform rules

[Network transform rules](/network/internet-access) now accept a single leading wildcard label, such as `*.example.com`, so one rule can transform requests to subdomains at any depth. Exact keys take precedence, and when several wildcards match, the most specific one applies. ([`d843e3f`](https://github.com/e2b-dev/infra/commit/d843e3f00d708e292c31a5841a2fe1fcfc1f2997))

### Server-side API key validation

The SDKs no longer check the `e2b_` [API key](/api-key) format on the client; the `validateApiKey` and `validate_api_key` options are deprecated and have no effect. The API validates keys instead and returns a distinct 401 message for a malformed key. Shipped in the JavaScript and Python SDKs 2.46.0. ([#1751](https://github.com/e2b-dev/E2B/pull/1751))

### Readable proxy errors for browser requests

Error responses synthesized in front of a sandbox, such as when the sandbox is unreachable, now carry CORS headers and answer preflight requests, so browser code can read the actual error instead of hitting a generic network failure. ([`32c6b84`](https://github.com/e2b-dev/infra/commit/32c6b84d4bacb515a94d0fa0252560f777faef08))

### Sandbox git module deprecation

The sandbox `git` module is deprecated as of the JavaScript and Python SDKs 2.46.1 and will be removed in the next major version. Run git through [`commands.run`](/commands) instead. ([#1774](https://github.com/e2b-dev/E2B/pull/1774))

### CLI configuration file scope

The CLI no longer reads `e2b.toml` outside `e2b template migrate`; the `sandbox create`, `template delete`, `template publish`, and `template unpublish` commands take the template as an argument instead of the `--config` and `--path` flags. This is a breaking change in CLI 2.18.0. ([#1761](https://github.com/e2b-dev/E2B/pull/1761))

### Fixes

- The CLI now passes flags placed after the command in `e2b sandbox exec` through to the remote command, and `e2b sandbox create --detach` prints only the sandbox ID to stdout. ([#1759](https://github.com/e2b-dev/E2B/pull/1759), [#1762](https://github.com/e2b-dev/E2B/pull/1762))
- Fixed the JavaScript SDK dropping a malformed `egressProxy` address instead of raising a clear error, and null proxy credentials are no longer sent to the API (SDK 2.46.0). ([#1757](https://github.com/e2b-dev/E2B/pull/1757))
- Fixed snapshot and template builds staying stuck in a non-terminal status after a client disconnect or a rejected pause. ([`8586a66`](https://github.com/e2b-dev/infra/commit/8586a66a5e84504536b2df9b7e28efe9069d8284), [`42f6997`](https://github.com/e2b-dev/infra/commit/42f699786534f1c0ad625ce9b4b7b922b3a16834), [`0159f8c`](https://github.com/e2b-dev/infra/commit/0159f8c0fa5b03c2a1bbe706f35ceea41bcd23c5))
- Fixed command starts in a sandbox that has exhausted memory or processes returning a generic error instead of a retryable resource exhaustion error. ([`f733a71`](https://github.com/e2b-dev/infra/commit/f733a713361e65633c2cb437c3de1ad755964a1a))
- Fixed streamed requests aborted mid-response ending with a cut connection instead of a proper error status. ([`3affe52`](https://github.com/e2b-dev/infra/commit/3affe5280b7e1cf8a182840cc50964a6bc5b569d))
- Fixed the dashboard webhook editor not offering the `sandbox.lifecycle.checkpointed` [event](/sandbox/lifecycle-events-webhooks).
- Self-hosted deployments no longer cache a missing platform file on AWS, which kept sandbox startup failing after the file became available, and failed multipart uploads to Google Cloud Storage are aborted instead of orphaning parts. ([`19ad718`](https://github.com/e2b-dev/infra/commit/19ad71816c3eda57d133f8145ef541dc609c2217), [`9e1caea`](https://github.com/e2b-dev/infra/commit/9e1caea40fc75eb2e07cbe75129db7d3eceb7e4e))

## Bring Your Own Proxy & Sandbox List Filters

This week routes sandbox egress through your own SOCKS5 proxy, adds sorting and filters to sandbox listing, and ships snapshot management commands in the CLI.

### Bring your own proxy for sandbox egress

`Sandbox.create` accepts a [`network.egressProxy`](/network/byop) option that tunnels every outbound TCP connection through a SOCKS5 proxy you operate, applied on the host after `allowOut` and `denyOut` so code inside the sandbox cannot see or route around it. `updateNetwork` swaps the proxy on a running sandbox, and egress fails closed when the proxy is unreachable. Shipped in the JavaScript and Python SDKs 2.41.0. ([#1688](https://github.com/e2b-dev/E2B/pull/1688))

### Sandbox list sorting and filters

[`Sandbox.list`](/sandbox/list) accepts an `order` option (`asc` or `desc`, default `desc`) that sorts by start time across the paginated dataset, plus `startedAfter` and `template` filters that apply server-side. The `e2b sandbox list` command exposes the same knobs through `--order`, `--started-after`, and `--template`. Shipped in the JavaScript and Python SDKs 2.45.0 and the CLI 2.17.0. ([#1735](https://github.com/e2b-dev/E2B/pull/1735), [`e6de33c`](https://github.com/e2b-dev/infra/commit/e6de33c74602b6ba116bb041e70e8bba73133550))

### Snapshot commands in the CLI

The [`e2b sandbox snapshot`](/cli/manage-snapshots) group adds `create <sandboxID>` with an optional `--name`, `list [sandboxID]` with a `--name` filter, and `delete <snapshotIDs...>`. Shipped in the CLI 2.17.0. ([#1741](https://github.com/e2b-dev/E2B/pull/1741))

### Machine-readable sandbox placement errors

A failed `POST /sandboxes` now returns a machine-readable `error_code` paired with a status: 503 with `cluster_at_capacity` or `no_compatible_node`, 504 with `placement_timeout`, and 500 with `sandbox_create_failed`, instead of a bare 500. ([`c426430`](https://github.com/e2b-dev/infra/commit/c4264309b3776dbd7b0d456d882afbb97187dc78))

### Multi-connection SDK client

The new [`E2B` client](/client) binds a connection config once and exposes `Sandbox`, `Volume`, and `Template` off it, so one process can talk to several API keys, domains, or self-hosted deployments in parallel. Shipped in the JavaScript and Python SDKs 2.44.0. ([#1720](https://github.com/e2b-dev/E2B/pull/1720))

### Refreshed MCP server catalog

The [MCP server catalog](/mcp-gateway/available-servers) picks up 49 new servers and drops six retired ones from the `McpServer` type, so `Template().addMcpServer("postgres")` stops compiling. Shipped in the JavaScript and Python SDKs 2.42.0. ([#1716](https://github.com/e2b-dev/E2B/pull/1716))

### Fixes

- Improved pause and resume reliability for sandboxes running systemd units under a slice or a nested container runtime, removing the tail of slow resumes those workloads used to see. ([`f06e9bc`](https://github.com/e2b-dev/infra/commit/f06e9bc1e2d605e1e11b65cc3242a8af0c7a3151))
- Fixed sandbox create failing with a retryable 500 when `denyOut` or `allowOut` contained a CIDR whose range ended at `255.255.255.255`, such as `240.0.0.0/4`. ([`9f6c2eb`](https://github.com/e2b-dev/infra/commit/9f6c2eb54efcaf32a087e854c689793dd01fd200))
- Fixed network `transform` rules with a wildcard host key such as `*.github.com` not matching connections whose TLS SNI matched the wildcard. ([`9072e15`](https://github.com/e2b-dev/infra/commit/9072e15e7b8a08fa47fee77f3236fff26ea93ac2))
- Fixed the Python SDK 2.45.1 buffering streamed request bodies across retries, so `files.write` of a file-like object and `volume.write_file` no longer scale peak memory with file size. ([#1718](https://github.com/e2b-dev/E2B/pull/1718))
- Fixed the JavaScript SDK 2.42.0 sending `autoResume` and `autoPause` local defaults on create when no lifecycle was configured, so the API can apply its own defaults. ([#1693](https://github.com/e2b-dev/E2B/pull/1693), [#1694](https://github.com/e2b-dev/E2B/pull/1694))
- Reliability and security hardening across platform services, including dependency and base image CVE patches.

## Workload Identity in the SDKs & Faster Python HTTP

This week ships sandbox workload identity in both SDKs, moves the Python SDK onto a Rust HTTP stack, and returns detailed sandbox placement failure reasons.

### Sandbox workload identity in the SDKs

`Sandbox.create` now takes an `iam` option with a `tokens` map defining short-lived [workload identity](/iam/workload-identity) tokens by audience and type, via the new `Secret.iamToken` helper (`Secret.iam_token` in Python). A network rule's `transform` can be a callback receiving token placeholders, so a token reaches egress request headers without the SDK seeing its value. Shipped in the JavaScript and Python SDKs 2.39.0. ([#1606](https://github.com/e2b-dev/E2B/pull/1606), [#1616](https://github.com/e2b-dev/E2B/pull/1616))

### Python SDK moves to a Rust HTTP stack

The Python SDK 2.38.0 routes the control plane, sandbox file transfers, volume content, and template build-context uploads through `pyqwest`, a Rust transport for `httpx`. Connection pools are now process-global per proxy, and `request_timeout` is a whole-transfer deadline. `E2B_MAX_CONNECTIONS` is no longer read. ([#1601](https://github.com/e2b-dev/E2B/pull/1601), [#1602](https://github.com/e2b-dev/E2B/pull/1602), [#1603](https://github.com/e2b-dev/E2B/pull/1603), [#1623](https://github.com/e2b-dev/E2B/pull/1623))

### Detailed sandbox placement failure reasons

A failed sandbox create or resume now returns a message naming the reason: cluster at capacity, no compatible node, placement timed out, snapshot files missing, or repeated create failures. Every case previously returned a bare `Failed to place sandbox`. ([`063aa20`](https://github.com/e2b-dev/infra/commit/063aa20c871116c80915ab1f5c2e81d804e6b2d0))

### Sandbox concurrency add-on management in the dashboard

The billing page in the [console](https://console.e2b.dev) lets you buy multiple sandbox concurrency add-on units, schedule a reduction or cancellation at the end of the billing period, and see plan and add-on costs itemized in the monthly total.

### Fixes

- Fixed sandbox proxy errors returning the HTML error page to browser `fetch()` and `XMLHttpRequest` callers that expected JSON, by using `Accept`, `Sec-Fetch-Mode`, and `X-Requested-With` before the User-Agent sniff. ([`d70ca24`](https://github.com/e2b-dev/infra/commit/d70ca24dbe1325b8f773b1435224efa862ae5156))
- Fixed sandboxes resumed from large snapshots losing the working set the platform preloads on resume when the snapshot upload took longer than expected, which made the next resume slower than it should be. ([`aeab31d`](https://github.com/e2b-dev/infra/commit/aeab31df792a293066a28286a80829e75db28463))
- Restored the `http2` parameter on the Python SDK 2.39.1 transport factories, so `http2=False` again returns a transport pinned to HTTP/1.1. ([#1671](https://github.com/e2b-dev/E2B/pull/1671))
- Reliability and security hardening across platform services, including dependency and base image CVE patches.

<Update label="August 10, 2026" description="Self-hosted proxy retirement, template cert repair, and SDK install fixes" tags={["Self-hosted", "Templates", "SDK"]} rss={{ title: "Self-Hosted Proxy Retirement & Template Cert Repair", description: "This week retires the deprecated reverse-proxy service on self-hosted clusters, repairs SSL trust stores baked into templates, and unblocks Python SDK installs alongside newer wcmatch." }}>

## Self-Hosted Proxy Retirement & Template Cert Repair

This week retires the deprecated reverse-proxy service on self-hosted clusters, repairs SSL trust stores baked into templates, and unblocks Python SDK installs alongside newer `wcmatch`.

### Reverse-proxy service retired on self-hosted clusters

Self-hosted deployments no longer build or ship the reverse-proxy service. `DOCKER_REVERSE_PROXY_VERSION` is removed from both `.env.aws.template` and `.env.gcp.template`, and a new `DOCKER_REVERSE_PROXY_ENABLED` toggle (default on) controls whether the AWS ECR repository is created and whether the GCP deployment runs. Clusters without a prebuilt `docker-reverse-proxy:latest` image must set the toggle to `false`. ([`d153bbe`](https://github.com/e2b-dev/infra/commit/d153bbe9d1e2ccd5e087d7c1dece5b8974175b54))

### Repaired SSL trust store in template builds

Template builds that install SSL-related packages such as `ca-certificates` or `openjdk` no longer leave the finalized template with a half-configured package or a silently broken Java trust store. Directory paths under `/etc/ssl/certs` claimed by installed packages are restored before the certificate bundle is packed. Existing broken templates need a rebuild. ([`6f17229a`](https://github.com/e2b-dev/infra/commit/6f17229a2a75695de19cbbba4f8f65a7f13ec6c5))

### Separate egress marking for template builds and sandboxes

On [BYOC](/byoc) clusters that opt in to [DSCP marking](/deployment/dscp-marking), template-build traffic can now carry a different DSCP value from sandbox traffic, so a downstream firewall or shaper can classify the two separately. An unset build value inherits the sandbox value, and an explicit `0` disables marking for builds only. ([`41c38cbe`](https://github.com/e2b-dev/infra/commit/41c38cbec4681192584139931ef294eaee8297d2))

### Python SDK installs alongside newer wcmatch

The Python SDK 2.37.1 relaxes its `wcmatch` requirement to `>=10.1,<12`, so `pip install e2b 'deepagents>=0.7.0'` and other combinations that pull in `wcmatch` 11 resolve without a conflict. ([#1638](https://github.com/e2b-dev/E2B/pull/1638))

### Public Git argument and status types in the JavaScript SDK

The JavaScript SDK 2.38.1 exports `GitResetMode`, `GitResetOpts`, `GitRestoreOpts`, and `GitStatusLabel` from the `e2b` package entry, so you can annotate wrappers around `sandbox.git.reset()`, `sandbox.git.restore()`, and `sandbox.git.status()` without inferring types. ([#1642](https://github.com/e2b-dev/E2B/pull/1642))

### Fixes

- Aligned the Python SDK 2.37.1 `strip_ansi_escape_codes` with the JavaScript SDK 2.38.1 `stripAnsi`, so template build logs are cleaned identically across languages and OSC, CSI, DCS, SOS, PM, and APC control sequences no longer leak into cleaned output. ([#1545](https://github.com/e2b-dev/E2B/pull/1545))
- Reliability and security hardening across platform services, including dependency and base image CVE patches.

<Update label="August 3, 2026" description="Access tokens disabled, multi-distro templates, and CLI session flags" tags={["Templates", "CLI", "SDK", "API"]} rss={{ title: "Access Tokens Disabled & Multi-Distro Templates", description: "Access tokens are now disabled; authenticate the CLI with E2B_API_KEY instead. ## Access Tokens Disabled & Multi-Distro Templates

Access tokens are now disabled, so authenticate the CLI with `E2B_API_KEY` instead. This week also improves templates and terminal workflows with Fedora, Alpine, Arch, and NixOS base images, CLI session flags, and cross-runtime detection of web platform objects.

### Access tokens are now disabled

As of August 1, 2026, E2B no longer accepts access tokens for authentication, completing the [`E2B_ACCESS_TOKEN` deprecation](/migration/access-token-deprecation) announced on June 22. Any CLI command or request still authenticated with an access token now fails. Authenticate the CLI with `E2B_API_KEY` instead, the same key the SDKs use. This also affects the V1 build system, which authenticated with the access token; see the [V1 build system deprecation](/migration/v1-build-deprecation) to migrate to V2 builds that use `E2B_API_KEY`.

### Fedora, Alpine, Arch, and NixOS base images

Templates can now start from Fedora, Alpine, and Arch [base images](/template/base-image) using the new `fromFedoraImage`, `fromAlpineImage`, and `fromArchImage` helpers in JavaScript SDK 2.37.0, or `from_fedora_image`, `from_alpine_image`, and `from_arch_image` in Python SDK 2.36.0. Base image provisioning identifies the distribution from `/etc/os-release`, and unsupported images fail the build with a clear reason. The premade `e2bdev/nixos` image adds NixOS support for images whose packages and services are declared in the image configuration. ([#3411](https://github.com/e2b-dev/infra/pull/3411), [#3412](https://github.com/e2b-dev/infra/pull/3412), [#1612](https://github.com/e2b-dev/E2B/pull/1612), [#1625](https://github.com/e2b-dev/E2B/pull/1625))

### Terminal session flags in the CLI

`e2b sandbox create` and `e2b sandbox connect` now accept `--user`, `--cwd`, and repeatable `--env KEY=VALUE` flags in `@e2b/cli` 2.16.1. The connected terminal starts as the given user, in the given working directory, and with the given environment variables. ([#1501](https://github.com/e2b-dev/E2B/pull/1501))

### Cross-runtime detection of web platform objects

The JavaScript SDK in version 2.37.0 now identifies `Request`, `Blob`, `File`, and `ReadableStream` values by shape rather than by class, so replacements installed by frameworks such as remix, `@hono/node-server`, and jsdom test environments no longer take the wrong branch. This fixes API calls failing with `Failed to parse URL from [object Request]`, uploads that silently contained the text `[object Blob]`, and `volume.readFile()` returning empty data. ([#1618](https://github.com/e2b-dev/E2B/pull/1618))

### BYOC volume endpoints return the cluster domain

Teams connected to a custom [BYOC cluster](/byoc) now receive their cluster domain from the volume create and get endpoints, and the SDKs route volume content requests to that host instead of the default `api.<E2B_DOMAIN>`. Teams on the default cluster keep their configured default. ([#3490](https://github.com/e2b-dev/infra/pull/3490))

### Cleaner installs of the JavaScript SDK and CLI

Installing `e2b` and `@e2b/cli` no longer prints deprecation warnings for the transitive `glob` package. The Python SDK ships a rebuilt transport for sandbox commands, filesystem, and PTY calls in version 2.35.0, replacing its vendored client. ## Sandbox Forking & Snapshot Name Filters

This week improves sandbox provisioning and snapshot workflows with in-place sandbox forking, name-based snapshot lookup, and Docker-compatible template file copying.

### Sandbox forking

You can now fork a running [sandbox](/sandbox) to spin up one or more clones from its exact in-memory state. The source is briefly paused, snapshotted, and resumed with its ID and expiration untouched, while each fork is returned independently as a running sandbox or a per-fork error. Use `sandbox.fork({ count, timeoutMs })` in JavaScript SDK 2.35.0 or `sandbox.fork(count=..., timeout=...)` in Python SDK 2.34.0. ([#3202](https://github.com/e2b-dev/infra/pull/3202), [#1554](https://github.com/e2b-dev/E2B/pull/1554))

### Snapshot filtering by name

`Sandbox.listSnapshots()` and `Sandbox.list_snapshots()` now accept a `name` filter matching a snapshot name or ID, optionally tag-qualified such as `"my-team/my-snapshot:v1"`. It combines with the existing sandbox ID filter and returns an empty page for unknown names. Available in JavaScript SDK 2.34.0 and Python SDK 2.33.0. ([#1523](https://github.com/e2b-dev/E2B/pull/1523))

### Docker-compatible template file copies

The [template `copy` step](/template/defining-template) now merges into existing destination directories instead of replacing them, matching Docker `COPY` semantics. Copying `src/` into an image that already has files under `/app/src/` preserves those entries and only overwrites what the source provides. ([#3283](https://github.com/e2b-dev/infra/pull/3283))

### Fixes

- Fixed template builds occasionally reporting a failed command stream as success, so build failures now surface reliably. ([#3281](https://github.com/e2b-dev/infra/pull/3281))
- Fixed [template builds](/template/build) sizing the root filesystem from stale free-space totals, which could leave the resized template short on space after an unclean shutdown. ([#3282](https://github.com/e2b-dev/infra/pull/3282))
- Fixed copying a template layer when the source snapshot contained only a filesystem image and no memory state. ([#3299](https://github.com/e2b-dev/infra/pull/3299))

<Update label="June 16, 2023" description="Protocol and smol updates">

## Agent Protocol

We have made first steps in developing the [Agent Protocol](https://github.com/e2b-dev/sdk/tree/main).

The protocol defines an interface for interacting with your agent. Adopting the protocol makes your agent automatically deployable to the e2b platform.

Our goal is to make this protocol open and usable in the whole agent field. This is a collaborative project. We're working on it with the most popular open-source agents, e.g., [Auto-GPT](https://github.com/Significant-Gravitas/Auto-GPT/?utm_source=awesome-ai-agents), [smol developer](https://github.com/smol-ai/developer), or [babyagi](https://github.com/yoheinakajima/babyagi).

**Objectives:**

- **Common endpoints** to communicate with an agent - "start", "step", "stop" for starters. More will come, especially around debugging, tracing, and monitoring
- **Tech-stack agnostic** - no specific framework required - you can adopt this without using the rest of SDK
- **Great DX** - easy to adopt and implement - no need to rewrite your existing agent
- **Open** - any agent builder can implement this and instantly become compatible with any platform supporting this protocol

If you like the protocol, please appreciate the [GitHub repo](https://github.com/e2b-dev/agent-protocol) with a star. [Contributors](https://github.com/e2b-dev) are welcome.
